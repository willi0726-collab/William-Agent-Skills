# Documentation Obsidian

## Overview

Use this skill to create clear Markdown documentation and Obsidian notes that are useful for retrieval, maintenance, and decision-making. Keep documentation proportional to the user's goal.

## Workflow

1. Identify the audience, purpose, target folder, naming convention, and whether the output is project docs or an Obsidian vault note.
2. Preserve existing structure, frontmatter, tags, aliases, and backlinks unless the user asks to reorganize.
3. Write concise Markdown with clear headings, stable links, and actionable summaries.
4. For Obsidian, prefer useful internal links over decorative linking. Use tags sparingly and consistently.
5. For project documentation, include prerequisites, commands, configuration, verification steps, and ownership only when relevant.
6. Verify links, filenames, and generated Markdown formatting before reporting completion.

## Common Outputs

- README sections
- SOPs and runbooks
- Meeting notes and decision logs
- Obsidian evergreen notes
- Maps of content
- Templates
- Migration cleanup plans

## Guardrails

Do not rewrite a user's voice-heavy notes unnecessarily. Do not reorganize a vault or docs tree broadly without explicit approval. Do not add speculative documentation for features that do not exist.
